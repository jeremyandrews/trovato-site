{# The comment thread and form. The kernel resolves `elements/comments` for every item page, builds the whole context for it, and ships no such template — so on a stock install the thread renders as nothing and the log carries `failed to render the comment thread … Template 'elements/comments.html' not found` on every item view. This is the site's. Context, all of it from `routes::comment::render_thread`: comments published comments, threaded, each with id, depth, created, author_name and body_html total how many item_id the item they belong to can_comment whether this viewer may post user_logged_in whether there is a viewer at all current_path where to come back to comment_outcome what happened to the last submission, if this is a redirect csrf_token only present when can_comment The form posts `application/x-www-form-urlencoded` to the same route the JSON API uses. The kernel accepts both encodings, takes the token from `_csrf` for a form, and answers a form with a redirect rather than JSON. So this works with JavaScript switched off, which is the point. #}
