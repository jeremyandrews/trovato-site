What happens when you search

Search here has three parts, and they do not all behave the same way. It is worth knowing which is which.

Keyword search runs in your browser

The site publishes its search index as static files. Your browser downloads the fragments it needs and runs the search locally, in WebAssembly. For this part there is no request to the server, no database query, and nothing about what you typed goes anywhere.

Without JavaScript, the server answers instead

The form above submits to the server, which runs a PostgreSQL full-text query and renders the results as a page. It is a round trip rather than instant, and it is always available. The instant search is an enhancement on top of it, not a replacement for it.

The AI features are server-side, and they send your query onward

Two of the four stages use a language model: one expands your query into related terms, and one writes a summary above the results. Both run on the server, and both send your query, and the snippets retrieved for it, to whichever AI provider the site is configured to use. That is a request to a third party, and no amount of the first paragraph being true changes it.

This site has no AI provider configured, so today those two stages do not run and nothing you type leaves this server. If that changes, this page changes with it and says which provider.
